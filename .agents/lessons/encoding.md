# Lessons: Encoding / 文字化け対策

Windows + PowerShell 環境での文字コード事故、CSS/JS への日本語コメント混入による破壊的事故への教訓。

## 📌 Master Rules

1. **Windows でファイル部分置換に PowerShell を使わない** — `Get-Content` / `Set-Content` のエンコーディング指定漏れで日本語が破壊される。専用 API ツール（Edit / Write）か Node.js (`fs.readFileSync('...', 'utf8')`) を使う。
2. **CSS/JS の末尾に日本語コメントを追記するのは慎重に** — 1 バイトの不正混入で以降のルールが全滅する。重要度の低いコメントは ASCII にするか、安全確認後の二段階コミットで添える。
3. **文字化けが疑わしい修正は即 `git checkout` で差し戻す** — 汚染されたファイルにさらに追記すると問題が悪化する。

## 教訓ログ

### 2026-04-12 [PowerShell][Encoding] PowerShell によるファイル部分置換で日本語破壊
→ サマリ昇格 (2026-04-12: PowerShell 文字化け禁止)

- **❌ Anti-pattern (どんなミスをしたか):**
  Windows環境のPowerShellで `Get-Content` / `Set-Content` を使ってソースファイルの文字列置換を行った際、エンコーディング指定が不十分で日本語が文字化け（Mojibake）してしまった。`>` リダイレクトは UTF-16LE で出力されるため、後続のツールで読めなくなることもある。

- **✅ Solution / Rule (どうすれば防げるか):**
  ファイルの部分置換を伴うコード修正には、必ず専用のAPIツール（`Edit` / `Write` 等）を使用するか、文字コードに安全な Node.js（`fs.readFileSync('...', 'utf8')`）を実行して置換を行うこと。安易な `>` リダイレクトや `Set-Content` は禁止。ターミナル実行時のエンコーディングルール（`.agents/workflows/terminal-encoding.md`）を参照すること。

### 2026-04-19 [Encoding][CSS][Comment] CSS/JS ファイルへの日本語コメント追記によるエンコーディング破損

- **❌ Anti-pattern (どんなミスをしたか):**
  CSSファイルの末尾に日本語のコメントを含むスタイルを追記した際、環境由来（PowerShell経由の出力等）の文字化けをそのまま含めてしまい、目に見えない不正なバイト列がファイルに混入した。
  これによりブラウザのCSSパーサーがエラーを起こし、追記部分以降の正常なCSSがすべて無視され、レイアウトが崩壊した。

- **✅ Solution / Rule (どうすれば防げるか):**
  1. **修正の「汚染」が疑われる場合は即座に差し戻す:** 一度文字化けが混入したファイルへの更なる追記は問題を悪化させる。不審な文字化けを見つけたら、すぐに `git checkout` またはファイルの末尾を切り落としてクリーンな状態に戻してから再試行すること。
  2. **重要度の低いコメントはASCII（英語）に切り替える:** 特に大きなCSS/JSファイルの末尾に追記する場合、日本語コメントが原因で全滅するリスクを避けるため、一時的に英語コメントに切り替えるか、安全が確認できてから日本語を添える「二段階コミット」をとること。
  3. **Node.jsによるクリーンな書き込み:** 重度の破損が発生した場合、Node.js の `fs` モジュール等を使って、明示的に `utf8` と指定して読み書きすることで、Windows特有のエンコーディングトラブルを回避できる。
